# Portal — HSCT(및 향후 다른 프로젝트) 통합 UI 셸

## 0. 이 문서의 목적

여러 프로젝트(HSCT 등)를 하나의 화면 안에서 오갈 수 있는 새 프론트엔드 셸(shell)을
만드는 작업이다. 2026-09-22 워드픽 세션에서 사용자와 레이아웃·범위를 확인만 하고
**실제 구현은 진행하지 않았다** — "다른 세션에서 시작할 거라 일단 네가 얼마나 이해하는지
물어본 것"(사용자 원문)이라, 다음 세션이 이 문서 하나만 읽고 바로 구현에 들어갈 수 있게
확인된 내용을 정리해둔다.

## 1. 레이아웃 (사용자가 그림으로 직접 제시, 화면을 4등분)

```
┌────────┬──────────────────────────────────────┐
│   ①    │              ②                        │
│  로고   │         대분류(앱 선택)                │
├────────┼──────────────────────────────────────┤
│        │                                        │
│   ③    │              ④                        │
│ 중분류  │         선택한 기능이 실제로            │
│ (기능   │         동작하는 메인 화면              │
│  목록)  │                                        │
│        │                                        │
└────────┴──────────────────────────────────────┘
```

- **① 로고(좌상단)**: 클릭하면 홈으로 이동하는 버튼.
- **② 상단바(로고 오른쪽, 가로 전체)**: **대분류** — 여러 프로젝트("앱")를 나열해 어느
  것을 쓸지 고르는 최상위 메뉴. 사용자 확인: "여러 프로젝트 통합"이 맞다(HSCT 하나만이
  아니라 향후 다른 실제 배포된 앱들도 여기 추가될 예정) — 단, **어떤 프로젝트들을 정확히
  포함할지는 아직 정하지 않았고, 한꺼번에 다 정하지 않고 "필요한 내용을 하나씩" 만들어가기로
  확정**했다(사용자 원문). 지금 확정된 건 **첫 번째로 HSCT부터 시작**한다는 것뿐이다.
- **③ 좌측 사이드바(②에서 고른 앱에 종속, 세로 전체)**: **중분류** — 그 앱 안의 개별
  기능 목록. HSCT를 예로 들면 지금 `public/index.html`에 있는 섹션들이 후보:
  1. 발주 데이터 엑셀 업로드(order-export, 17컬럼)
  2. 레거시 업로드(URL·상품명·도착국 3컬럼)
  3. 일본어 상품명 → 한국어 번역
  4. 학습 데이터 직접 업로드
  5. 주문내역 재검토(AI분석실패) — order-status, 2026-09-22 신설분(가장 최근 기능)
- **④ 메인 영역(우측 대부분)**: ③에서 고른 기능이 실제로 동작하는 화면. **페이지 전체
  리로드 없이 같은 자리에서 상태가 바뀌는 방식**을 사용자가 직접 예시로 듦: "발주데이터
  업로드하고, 업로드 완료되면, 페이지가 바뀌면서 제안 결과 확인 및 편집으로 넘어간다."

## 2. 확정된 원칙

1. **기존 앱들의 주소는 그대로 둔다.** 지금의 `E:\Tools\HScodeTOOL\public\index.html`
   (및 그 API들)은 손대지 않는다 — URL도 코드도 그대로.
2. **완전히 새로운 페이지 1개**를 만들어 그 페이지가 4분할 셸 역할을 한다. 백엔드는
   재사용(같은 `/api/upload`, `/api/upload/order-status`, `/api/download` 등을 ④ 영역
   안에서 그대로 호출) — **새로 만드는 건 프론트엔드 껍데기뿐**이다.
3. **한꺼번에 다 만들지 않고 단계적으로 간다**(사용자 명시: "앱 목록은 한꺼번에 하기보다
   필요한 내용을 하나씩 만들어가자"). 다음 세션이 시작할 최소 단위로 워드픽 세션에서
   제안했고 사용자가 반대하지 않은 순서:
   - 1단계: ①②③④ 뼈대만 먼저(정적 레이아웃) — 상단바(②)엔 우선 **HSCT 하나만**,
     사이드바(③)엔 위 5개 기능 목록을 넣되, ④는 아직 빈 화면/자리표시자로.
   - 2단계: 5개 기능 중 **"주문내역 재검토"를 첫 실제 동작 기능으로** ④에 연결(워드픽
     세션에서 이렇게 제안했고 사용자가 반대하지 않았으나, **명시적으로 확정 답변을 받은
     건 아니므로 다음 세션 시작 시 한 번 더 확인 권장**). 나머지 4개 기능은 "준비 중"
     표시만 해두고 이후 하나씩 연결.
4. 파일 위치는 논의 안 됐지만, 워드픽 세션에서 제안했던 방향: `public/portal.html`
   (+ 필요시 `public/portal.js`/`public/portal.css` 분리) 형태로 HSCT의 `public/`
   폴더 안에 새 정적 파일만 추가 — `express.static()`이 이미 `public/` 전체를 서빙하므로
   `server.js`에 새 라우트를 추가할 필요 없이 `/portal.html`로 바로 접근 가능하다. **이
   경로·파일명도 아직 사용자 확정을 받은 건 아니다** — 다음 세션에서 시작 전 확인할 것.

## 3. 아직 미확정 — 다음 세션 시작 시 확인할 것

1. **포함할 프로젝트(앱) 전체 목록**: HSCT 다음으로 어떤 프로젝트를 추가할지(예:
   wordPICK-service 등 실제 배포된 다른 Railway 프로젝트가 후보로 언급됐으나 확정 아님).
2. **④ 영역의 첫 기능이 정말 "주문내역 재검토"가 맞는지** 재확인.
3. **파일 경로/파일명**(`public/portal.html` 등) 확정.
4. **CSS/시각 스타일**: 기존 `public/styles.css`를 재사용할지, 새 스타일시트를 만들지 —
   워드픽 세션에서 기존 `styles.css`를 훑어보기만 하고 결정은 안 했다.
5. 실행 게이트 원칙 그대로 — 위 미확정 사항이 정리되기 전에는 실제 구현(코드 작성)
   시작하지 말 것(2026-09-22 워드픽 세션에서 사용자가 "일단 구현은 하지마"로 명시
   중단시킨 바 있음 — 설계 확인 단계였을 뿐, 구현 승인은 아직 없었다).

## 4. 작업 로그

### 2026-09-22 — 레이아웃·범위 확인만 진행(구현 없음), 이 폴더·문서 신설

사용자가 4분할 레이아웃 그림을 제시하고 이해도만 확인 요청 → 설명 후 두 차례
AskUserQuestion으로 범위 확인(여러 프로젝트 통합 확정, 단 목록은 미정 / HSCT부터 시작

한 것"이라며 이 요약 문서 작성 요청. 코드는 전혀 작성하지 않았다(기존 `styles.css`
참고차 읽기만 함).
